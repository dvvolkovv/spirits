# Пересборка экрана входа

**Дата:** 2026-08-07
**Скоуп:** Фронт (`spirits_front`)
**Зависимости от бэка:** нет

## Контекст

Экран входа (`OnboardingPage` + `components/onboarding/*`) собирался слоями под разные задачи, и следы каждого слоя видны одновременно. Разбор текущего состояния:

**Пять языков иконок на одном экране.** Эмодзи (`🎁` в строке про токены, флаг страны в выпадашке языка), буквы в плашках с разной заливкой (красный квадрат `Я` у Yandex, белый с рамкой `G` у Google), растровый PNG у Taler ID, контурные lucide во вкладках Email/SMS, и `ArrowRight` внутри кнопки — только у телефона.

**Кнопки трёх разных ростов стоят стопкой.** OAuth — контур, `py-3`. Кнопка email — заливка, `py-2`. Кнопка телефона — заливка, `py-3` плюс `shadow-md hover:shadow-lg`, единственная с тенью.

**Поля ввода не совпадают между вкладками.** Email: `px-3 py-2`, кегль по умолчанию, `focus:ring-1`, лейбл обычным начертанием. Телефон: `px-4 py-3`, `text-lg`, `focus:ring-2`, лейбл полужирный с вдвое большим отступом.

**Ошибки показываются тремя способами.** Системный `alert()` (сбой OAuth, сбой отправки SMS), инлайн `text-red-500` (неверный номер), инлайн `text-red-600` (сбой отправки ссылки).

**Главная проблема не в иконках.** При первом заходе всё ниже галочки согласия отрисовано с `opacity-40 pointer-events-none` — человек видит серую нерабочую форму и подпись «Сначала примите условия выше». До формы идёт стек из десяти блоков: логотип 96×96, заголовок, выпадашка языка, подзаголовок, строка про токены, серая карточка согласия, три кнопки провайдеров, разделитель, вкладки, форма.

### Данные по способам входа

За 30 дней до 2026-08-07, с исключением тестовых аккаунтов (`70000000000`, `79030169187`, `79169403771`, `79656445804`, шаблон `790300\d{5}`, почты `claude.*@linkeon.io`):

| способ | людей | входов | регистраций |
|---|---|---|---|
| телефон (SMS) | 19 | 30 | 11 |
| Yandex | 4 | 5 | 3 |
| email-ссылка | 3 | 5 | 5 |
| Taler ID | 2 | 5 | 2 |

Сырые цифры без фильтрации показывают 4565 входов «по телефону» — это почти целиком smoke-набор, который логинится на каждом деплое. Из 46 входов по email 41 приходится на тестовый `claude.itest@linkeon.io`.

Объёмы малы (21 регистрация за месяц), выводов уровня «данные показали» на них строить нельзя. Приводятся как наблюдение.

Magic-link проверен и работает: ссылки уходят на внешние домены (bk.ru 13.07, yandex.ru 17.07, mail.ru 25.07). Ошибки `550 relay not permitted` в логах есть, но все четыре — от 28.05, времени настройки релея, и с тех пор не повторялись.

## Решения, принятые при проектировании

1. **Скоуп** — косметика плюс перекомпоновка блоков. Сценарий входа (какие способы есть и как они работают) не меняется.
2. **Согласие** — галочка остаётся явной и фиксируемой, но переезжает вплотную к главной кнопке. Форма больше не гасится целиком; вместо этого неактивна одна кнопка.
3. **Приоритет — вход по почте.** Решение владельца продукта. Наблюдения по регистрациям говорят в пользу телефона, но сторона расходов на SMS в этих цифрах не отражена. Телефон при этом остаётся полноразмерной кнопкой, а не мелкой сноской.
4. **Логотип Google не перекрашивается** — это против брендбука провайдера. Единообразие достигается одинаковыми слотами под знаки, а не приведением самих знаков к одному цвету.

## Архитектура

### Новые файлы

**`src/components/ui/controlStyles.ts`** — чистые функции, собирающие строки классов. Вынесены отдельно, потому что тестовое окружение проекта (`environment: 'node'`) не умеет рендерить React: так вся логика системы остаётся покрытой, а компоненты — тонкими.

```ts
export function buttonClasses(variant: ButtonVariant, extra?: string): string;
export function fieldClasses(hasError: boolean, extra?: string): string;
export const CONTROL_HEIGHT = 'h-11';
export const CONTROL_RADIUS = 'rounded-xl';
```

**`src/components/ui/Button.tsx`** — единственная кнопка приложения для экрана входа.

```tsx
type ButtonVariant = 'primary' | 'secondary' | 'ghost';

interface ButtonProps extends React.ButtonHTMLAttributes<HTMLButtonElement> {
  variant?: ButtonVariant;   // по умолчанию 'primary'
  loading?: boolean;         // показывает Loader из lucide вместо содержимого
  leading?: React.ReactNode; // значок слева в слоте фиксированного размера
}
```

Общее для всех вариантов: высота 44 px (`h-11`), `rounded-xl`, `text-sm font-medium`, `w-full`, переход `transition-colors`, `disabled:opacity-50 disabled:cursor-not-allowed`, фокус `focus-visible:ring-2 focus-visible:ring-forest-700/40`. Теней нет ни у одного варианта.

- `primary` — `bg-forest-800 text-white hover:bg-forest-900`
- `secondary` — `bg-white border border-gray-200 text-gray-700 hover:bg-gray-50`
- `ghost` — `text-forest-800 border border-forest-200 bg-white hover:bg-forest-50`

**`src/components/ui/TextField.tsx`** — поле с лейблом и ошибкой.

```tsx
interface TextFieldProps extends React.InputHTMLAttributes<HTMLInputElement> {
  label: string;
  error?: string | null;
  prefix?: React.ReactNode; // слот слева внутри рамки — под CountrySelect
}
```

Высота и радиус совпадают с кнопкой: `h-11 rounded-xl px-3.5 text-[15px]`, рамка `border-gray-200`, фокус `focus:border-forest-700 focus:ring-2 focus:ring-forest-700/20`. Лейбл — `text-sm text-gray-600 mb-1.5`. Ошибка — `text-sm text-red-600 mt-1.5`, всегда под полем.

**`src/components/onboarding/providerMarks.tsx`** — знаки провайдеров.

Экспортирует `providerMark(provider): React.ReactNode`. Каждый знак отдаётся в одинаковом слоте `w-[18px] h-[18px] shrink-0`: Google — встроенный SVG официального четырёхцветного «G»; Yandex — встроенный SVG фирменного знака; Taler ID — существующий `/talerid-logo.png`, приведённый к тому же размеру. Растровые и векторные знаки визуально уравниваются слотом, а не правкой самих знаков.

### Изменяемые файлы

**`src/pages/OnboardingPage.tsx`** — компоновка страницы.

Фон-градиент остаётся. Шапка сжимается: знак 56×56, название, одна строка подзаголовка (включая `seg`-варианты для рекламных сегментов — логика выбора подзаголовка не меняется). Форма уезжает в карточку `bg-white rounded-2xl border border-gray-100 shadow-[0_10px_30px_-14px_rgba(15,118,110,0.4)]`. Пилюля языка — абсолютом в правом верхнем углу. Строка про токены — под карточкой, пилюлей `bg-forest-50 text-forest-800 rounded-full`, без эмодзи.

Логика записи `referral_slug` из `?ref` не трогается.

**`src/components/onboarding/LoginTabs.tsx`** — порядок блоков внутри карточки.

Вкладки Email/SMS убираются. Вместо них — понятие **основной формы**: в карточке одновременно показана ровно одна форма, почты или телефона, а переключение идёт кнопкой на месте, без вкладок.

Порядок сверху вниз: основная форма → галочка согласия → главная кнопка → разделитель «или» → три кнопки провайдеров → кнопка перехода ко второй форме.

- Основная форма — почта: поле, кнопка «Получить ссылку для входа», внизу `ghost`-кнопка «Войти по номеру телефона».
- Основная форма — телефон: `CountrySelect` с полем, кнопка «Отправить код», внизу `ghost`-кнопка «Войти по почте».

Переключение меняет содержимое карточки на месте (`useState`), навигации нет. Введённое значение второй формы не сохраняется при переключении — обе формы одношаговые, терять нечего.

Ключ `lastLoginTab` в localStorage сохраняется и продолжает означать то же самое: какая форма открыта при заходе. Кто в прошлый раз входил по SMS — увидит форму телефона; новый человек — форму почты.

Блок `opacity-40 pointer-events-none` и подпись «Сначала примите условия выше» удаляются. Вместо них — `disabled` на главной кнопке и на кнопках провайдеров, пока галочка не отмечена.

**`src/components/onboarding/LoginConsentBlock.tsx`** — компактный вид.

Серая карточка `bg-gray-50 rounded-lg p-4` убирается: остаётся строка из галочки и текста `text-xs leading-relaxed`, стоящая вплотную над кнопкой. Модалки `LegalModal` и `PaymentInfoModal` подключаются как раньше.

**`src/components/onboarding/OAuthButton.tsx`** — на `Button variant="secondary"` со знаком из `providerMarks`. Локальные `LOOKS.badge` удаляются, `label`/`providerName` остаются. `alert()` при сбое заменяется на `toast.error`.

**`src/components/onboarding/EmailLoginPane.tsx`** — на `TextField` и `Button`. Экран «проверь почту» приводится к тем же отступам и кеглям.

**`src/components/onboarding/SmsLoginPane.tsx`** — `alert()` при сбое отправки SMS заменяется на `toast.error`. Ветка ошибок (включая `STORAGE_FULL`) не меняется.

**`src/components/onboarding/PhoneInput.tsx`** — на `TextField` с `prefix={<CountrySelect/>}` и `Button`. `ArrowRight` из кнопки убирается: у кнопки почты его нет, значит это украшение одного экземпляра.

**`src/components/onboarding/OTPInput.tsx`** — ячейки кода приводятся к радиусу и фокус-рингу системы; кнопки «Назад» и «Отправить повторно» — на `ghost`.

**`src/components/settings/LanguageSelect.tsx`** — добавляются два необязательных пропса:

```tsx
variant?: 'default' | 'pill';  // по умолчанию 'default'
showFlag?: boolean;            // по умолчанию true
```

`pill` рендерит тот же нативный `<select>` (нативный пикер на мобильном сохраняется) с `appearance-none` и значком `Globe` слева. `showFlag={false}` убирает эмодзи-флаг из подписей. Экран входа передаёт `variant="pill" showFlag={false}`; вызовы в `SettingsView` и `ProfileView` не трогаются и работают как раньше.

### Правила системы

- **Иконки** — только lucide, 18–20 px, одна толщина обводки. Эмодзи в интерфейсе не используются. Исключение — знаки провайдеров, они фирменные.
- **Кнопки и поля** — одна высота 44 px, один радиус `rounded-xl`, один фокус-ринг. Персональных теней нет.
- **Ошибки** — `text-red-600`, всегда под полем, через `TextField`. `alert()` не используется; для сбоев, не привязанных к полю, — `toast.error` (`react-hot-toast` уже подключён в `App.tsx`).
- **Отступы** — шаг 4 px: между полем и кнопкой 12, между смысловыми блоками 20, поля карточки 20.

## Что не меняется

- Логика авторизации целиком: `authService`, `AuthContext`, `apiClient`, `tokenManager`.
- Состав способов входа: Yandex, Google, Taler ID, email, SMS.
- Тексты в локалях. Исключения: удаляется `auth.consent.needToAccept` (подпись «Сначала примите условия выше» больше не показывается), добавляются подписи кнопок переключения формы.
- `data-testid`: `onboarding-root`, `consent-checkbox`, `phone-input`, `phone-submit-btn`, `otp-input-0`. Переносятся на соответствующие элементы новой разметки без переименования, плюс добавляются недостающие для новых элементов (`email-input`, `email-submit-btn`, `switch-to-phone`, `switch-to-email`, `oauth-<provider>`).

## Тестирование

### Текущее покрытие: ноль

Проверено 2026-08-07: экран входа не покрыт ни одним автотестом. `spirits_back/tests/playwright/smoke.spec.js` логинится **в обход интерфейса** — функция `loginViaStorage` получает JWT через API, подсаживает `jwt_access_token`/`authToken`/`userData` в localStorage через `addInitScript` и сразу открывает `/chat`. Ни один тест в `spirits_back/tests/` не обращается к перечисленным `data-testid`.

Отсюда два следствия. Smoke не сломается от пересборки — но и не докажет, что она ничего не сломала. И именно отсутствие покрытия объясняет, почему баг входа при переполненном localStorage (см. коммит `4b906ad`) прожил на проде незамеченным.

### Что добавляем

- **Юнит.** Vitest в проекте настроен на `environment: 'node'`, без `jsdom` и `@testing-library` — рендерить React-компоненты в тестах сейчас нельзя. Тянуть три девзависимости ради кнопки не будем. Вместо этого логика классов выносится в чистый модуль `src/components/ui/controlStyles.ts` и тестируется как есть; `Button` и `TextField` остаются тонкими обёртками без собственной логики. Реальное поведение проверяет Playwright.
- **Playwright по экрану входа** — новый файл `spirits_back/tests/playwright/login-ui.spec.js`, гоняющий интерфейс, а не обходящий его:
  1. галочка согласия выключает и включает главную кнопку и кнопки провайдеров;
  2. полный вход по SMS через интерфейс — переключение на форму телефона, ввод номера, код из `/webhook/debug/sms-code/`, попадание на `/chat`;
  3. регрессия на переполненный localStorage: то же самое при забитом хранилище должно заканчиваться входом, а не ошибкой;
  4. запрос magic-link по почте доходит до экрана «проверь почту».

  Тесты делятся на два вида, и путать их нельзя. **Характеризующие** (полный вход по SMS, вход при забитом localStorage, запрос magic-link) пишутся первыми и должны проходить **и до, и после** пересборки: их работа — доказать, что редизайн ничего не сломал. **Тесты нового поведения** (форма кликабельна без галочки, неактивна только кнопка, есть кнопка переключения формы) обязаны падать на текущей разметке — там форма гасится целиком, — и проходить после.
- **Ширины.** Ручная проверка на 320, 375, 420, 768, 1280.
- **Локали.** Все шесть (`ru`, `en`, `es`, `de`, `fr`, `zh`) — немецкий даёт самые длинные подписи, на нём проверяется, что кнопки не разъезжаются. Ключ `auth.consent.needToAccept` удаляется из всех шести файлов одновременно: за согласованность локалей отвечает `scripts/check-locales.test.mjs`, он упадёт на расхождении.

## Не входит в скоуп

- Перевод остального приложения на `Button`/`TextField`. Примитивы вводятся и применяются только на экране входа; распространение — отдельная задача.
- Пересмотр того, какие способы входа показывать и в каком приоритете, по данным. Обсуждалось, отложено: объёмов для выводов не хватает.
- Тёмная тема.
- Замена нативного `<select>` в выборе языка и страны на кастомный дропдаун.
