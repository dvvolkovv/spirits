# Кнопка «Прослушать» под ответом ассистента — дизайн

**Дата:** 2026-10-06
**Затрагивает:** `spirits_back` (`src/speech/*`: новая ручка, разбиение текста, таблица `speech_listens`), `spirits_front` (`ChatInterface.tsx`, новый каталог `src/components/chat/listen/`, локали ×7). Flutter-приложение, TG-бот и релей не меняются.

## Задача

Владелец: «нужно ещё сделать возможность прослушать ответ ассистента, чтобы рядом с количеством токенов и копировать была кнопка прослушать ответ».

Решение владельца (06.10.2026): **голос ассистента, платно**. Голос берётся тот, что выбран для ассистента в «Настройках → Голоса». Тариф тот же, что у озвучки по просьбе в чате: 1000 токенов за каждую начатую 1000 знаков. Повторное прослушивание того же ответа бесплатно. Цена видна в подсказке у кнопки.

Канал — веб, включая Capacitor-сборку `io.linkeon.app`: она грузит этот же фронт. Голос браузера (`speechSynthesis`) отвергнут: в Android WebView его нет, звучит он везде по-разному и с выбранным в настройках голосом не совпадает.

## Что есть сейчас

- **`SpeechService.synthesize`** (`spirits_back/src/speech/speech.service.ts`) вызывается только инструментом `generate_speech` из чата. Он выбирает голос (`resolveVoice`: выбор пользователя → дефолт ассистента → дефолт по полу), берёт Yandex для `ru` и OpenAI для остальных языков, кэширует клип в `speech_clips` по `(user_id, sha256(text voice lang))` и списывает `tokenCostFor(chars)` условным UPDATE со строкой в `token_transactions`. Лимит длины — 2000 знаков у Yandex и 4000 у OpenAI. Лимит частоты — 20 вызовов в минуту на пользователя (`speech:rl:<userId>`).
- **HTTP-ручки синтеза у фронта нет.** `SpeechController` отдаёт только `GET /webhook/speech/voices` и `GET /webhook/speech/:id`.
- **`POST /webhook/tts`** (`src/voice/tts.controller.ts`) — другая озвучка: голосовой цикл лаунчера, один голос `alloy`, до 1000 знаков, без кэша. Для кнопки не подходит.
- **Чат подхватывает клипы по времени.** В конце стрима `chat.service.ts` вставляет маркер `{{audio:id=…}}` для каждой строки `speech_clips` с `created_at` или `last_used_at` позже начала стрима и прибавляет их `tokens_spent` к счётчику «X токенов». Если клип прослушивания попадёт в `speech_clips`, а прослушивание случится во время ответа, этот ответ получит чужой плеер и чужую цену. Поэтому прослушивания живут в своей таблице.
- **Фронт.** Строка под ответом (`ChatInterface.tsx`, блок `flex items-center gap-2 text-xs mt-1`) показывает время, «• N токенов» и кнопку «Копировать». `selectedAssistant.name` — внутреннее имя ассистента: оно же уходит в `change-agent`, оно же ключ `profile_data.assistant_voices` и `ASSISTANT_DEFAULTS`.

## Бэкенд

### Ручка `POST /webhook/speech/listen`

`JwtGuard`. Тело запроса:

```json
{ "text": "чистый текст для чтения", "assistant": "Роман" }
```

`text` фронт готовит сам: разметка, служебные теги и эмодзи из него уже убраны. Бэк считает цену по длине именно этого текста.

`assistant` необязателен. Это строка до 64 знаков после `trim`. Без неё берётся `preferred_agent`, без него — «Роман». Подделка имени ничего не даёт: оно выбирает голос только из собственной карты пользователя и дефолтов.

Ответы:

| Статус | Тело | Когда |
|---|---|---|
| 200 | `{ ok: true, parts: string[], chars, tokensSpent, cached, voice, provider }` | готово; `parts` — публичные URL кусков в порядке чтения |
| 400 | `{ ok: false, error: 'empty_text' }` | пустой текст |
| 400 | `{ ok: false, error: 'text_too_long', maxChars: 10000 }` | длиннее 10 000 знаков |
| 402 | `{ ok: false, error: 'insufficient_tokens', balance, required }` | не хватает токенов |
| 429 | `{ ok: false, error: 'rate_limited', retryAfterSec: 60 }` | больше 20 синтезов в минуту |
| 502 | `{ ok: false, error: 'tts_failed' }` | провайдер не ответил и после ретрая |

### `SpeechService.listen(userId, { text, assistant })`

1. `trim`, проверка на пустоту и на потолок `LISTEN_MAX_CHARS = 10_000`. Это примерно 11 минут речи и 5 запросов к Yandex.
2. Лимит частоты — тот же счётчик `speech:rl:<userId>`, что у `synthesize`: один запрос = одно попадание. Бюджет 20 в минуту общий с инструментом.
3. Язык — `resolveUserLanguage`. Голос — `resolveVoice({ lang, assistantName, userChoice })`, где `userChoice = profile_data.assistant_voices[assistantName]`. Параметра `voice` у ручки нет.
4. Кэш: `cache_key = cacheKeyFor(text, voice, lang)`, поиск в `speech_listens` по `(user_id, cache_key)`. На попадании обновляется `last_used_at`, ответ `cached: true, tokensSpent: 0`.
5. Цена `required = tokenCostFor(text.length)` — **один раз на весь текст**, а не по кускам: округление вверх на каждом куске переплачивало бы до 1000 токенов за кусок.
6. Предпроверка баланса. При нехватке — 402 без обращения к провайдеру.
7. `splitForSpeech(text, maxCharsFor(provider))` режет текст на куски не длиннее лимита провайдера. Граница ищется по абзацам, потом по предложениям, потом по пробелу; слово длиннее лимита режется жёстко. Пустых кусков нет, порядок и содержимое сохраняются.
8. Синтез кусков — существующий `synthesizeWith` (один ретрай), не больше 3 запросов к провайдеру одновременно. Любой отказ — 502: ничего не списано и не сохранено.
9. Заливка кусков в MinIO: `audio/listen/<cache_key>-<i>.mp3`, `Cache-Control: public, max-age=31536000, immutable`.
10. Вставка в `speech_listens` с `ON CONFLICT (user_id, cache_key) DO NOTHING`. Если гонку выиграл параллельный запрос, возвращается его строка бесплатно.
11. Списание — как в `synthesize`: транзакция на выделенном соединении, `UPDATE … SET tokens = tokens - $1 … AND tokens >= $1` и строка в `token_transactions` (`consumed`, «Озвучка ответа», в metadata — `listen_id`, `chars`, `parts`, `voice`, `provider`). Если UPDATE не нашёл строки (баланс ушёл за время синтеза), вставленная строка удаляется адресно по id, ответ 402. Куски в MinIO без строки недостижимы.

Общие части с `synthesize` (выбор голоса по пользователю и ассистенту, списание с реестром) выносятся в приватные методы. SQL-текст списания не меняется: тесты `synthesize` сверяют его регулярками.

### Таблица `speech_listens`

`src/speech/migrations/002_speech_listens.sql`:

```sql
CREATE TABLE IF NOT EXISTS speech_listens (
  id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id      text NOT NULL,
  assistant    text,
  cache_key    text NOT NULL,
  parts        jsonb NOT NULL,
  chars        int NOT NULL,
  provider     text NOT NULL,
  voice        text NOT NULL,
  lang         text NOT NULL,
  tokens_spent int NOT NULL DEFAULT 0,
  created_at   timestamptz NOT NULL DEFAULT now(),
  last_used_at timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX IF NOT EXISTS speech_listens_user_key ON speech_listens (user_id, cache_key);
```

`user_id text`: у email/OAuth-пользователей это UUID, а не телефон. Накат делает `SpeechService.onModuleInit` по образцу `routine-push`: применяет все `.sql` модуля по порядку (`001` идемпотентна). Каждый файл идёт в своей транзакции на выделенном соединении с `SET LOCAL lock_timeout = '3s'`, ошибка пишется в лог и не роняет старт API. `npm run migrate` на проде сломан (застревает на `base/001`), поэтому на него не полагаемся.

`chat.service.ts` эту таблицу не читает. Прослушивание во время идущего ответа не добавляет в него ни плеера, ни цены.

## Фронтенд

### `src/components/chat/listen/speechText.ts`

- `toSpeechText(content)` — текст, который реально прочитают вслух. Обработка такая:
  - маркеры `[VIDEO_JOB:…]` и `[CALENDAR_PROPOSAL:…]` удаляются;
  - блоки вопросов идут через `askBlocksToPlainText`;
  - `{{link: Текст | url}}` превращается в «Текст», остальные `{{…}}` (кнопки, аудио, звонки, встречи) удаляются;
  - блоки кода, картинки, голые URL, HTML-теги, линии `---` и строки-разделители таблиц удаляются;
  - у ссылок `[текст](url)` остаётся текст, у инлайн-кода — содержимое;
  - маркеры заголовков, списков, цитат и выделения (`#`, `-`, `1.`, `>`, `**`, `__`, `~~`, одиночные `*`/`_` по краям слов) снимаются;
  - ячейки таблицы склеиваются через запятую;
  - эмодзи удаляются;
  - строка без знака конца предложения получает точку, чтобы синтезатор сделал паузу;
  - пробелы схлопываются, абзацы сохраняются переводом строки.
- `LISTEN_MAX_CHARS = 10_000` и `listenPrice(chars) = ceil(chars / 1000) * 1000` — зеркала констант бэка. Комментарии в обоих репозиториях ссылаются друг на друга. Бэк остаётся источником истины: при расхождении он ответит 400 или спишет по-своему.

### `useListenPlayer` (`src/components/chat/listen/useListenPlayer.ts`)

Один экземпляр на `ChatInterface`, один общий `HTMLAudioElement`. Одновременно звучит не больше одного ответа.

- Состояние — `{ id: string | null, phase: 'idle' | 'loading' | 'playing' }`.
- `toggle(id, text, assistant)`. Повторное нажатие на активный ответ останавливает его. Нажатие на другой ответ глушит текущий и запускает новый.
- **Разблокировка звука.** В обработчике нажатия, синхронно, элемент проигрывает беззвучный WAV-клип (`data:` URI, CSP на проде нет). Без этого iOS Safari и WKWebView откажут в `play()` после нескольких секунд синтеза.
- `parts` запоминаются в памяти по `(id, text)`: повтор в той же сессии не ходит на бэк. После перезагрузки страницы повтор бесплатен за счёт кэша бэка.
- Куски играются подряд: `ended` переключает на следующий, после последнего — `idle`.
- Каждый запуск и каждая остановка увеличивают номер прогона. Отставшие ответы и события старого прогона ничего не трогают. Запрос отменяется через `AbortController`. Бэк при этом может досинтезировать и списать, зато следующий повтор бесплатен.
- Остановка срабатывает при смене ассистента и при размонтировании.
- Ошибки показываются тостом (`react-hot-toast`, как в остальном чате):
  - 402 — «не хватает токенов, нужно N»;
  - 429 — «слишком часто, через минуту»;
  - 400 `text_too_long` — «слишком длинный ответ»;
  - отказ `play()` — «нажмите ещё раз», куски остаются в памяти;
  - сеть, 5xx и ошибка загрузки аудио — общий текст «не удалось озвучить».

### `ListenButton` (`src/components/chat/listen/ListenButton.tsx`)

`React.memo`. Текст для чтения считается `useMemo` от `content`, поэтому стриминг не гоняет регулярки по всей ленте. Если текст пустой (в ответе только картинка или плеер), кнопки нет. Вид кнопки повторяет «Копировать» (`inline-flex items-center gap-1 text-gray-400 hover:text-forest-600`):

| Фаза | Иконка | Надпись |
|---|---|---|
| idle | `Volume2` | «Прослушать» |
| loading | `Loader2` (крутится) | «Озвучиваю…» |
| playing | `Square` | «Остановить» |

`title` и `aria-label` в покое: «Прослушать ответ голосом ассистента: 2 000 токенов, повторно — бесплатно». Число форматирует `formatNumber`, единица берётся из `chat.tokens_suffix`. Цена всегда кратна 1000, поэтому форма множественного числа в каждом языке одна, и плюральные ключи не нужны. Если текст длиннее `LISTEN_MAX_CHARS`, кнопка `disabled`, а в подсказке написано почему.

### `ChatInterface.tsx`

- `const listen = useListenPlayer()` и остановка в эффекте на `selectedAssistant?.id`.
- В строке под ответом сразу после «Копировать» стоит `<ListenButton …/>` с тем же условием `message.type === 'assistant' && !message.isStreaming && message.content`.
- Строка получает `flex-wrap`, чтобы на узком экране кнопки переносились, а не вылезали за пузырь.

### Локали

Ключи `chat.listen`, `chat.listen_loading`, `chat.listen_stop`, `chat.listen_title`, `chat.listen_too_long`, `chat.listen_no_tokens`, `chat.listen_rate_limited`, `chat.listen_failed`, `chat.listen_tap_again` — во всех семи локалях. Источник правды — `ru.json`, переводы пишутся руками: `translate-locales` без ключа переписывает локаль. В UI — «ассистент», не «агент».

## Тесты

- **Бэк (jest, на ноде):**
  - `splitForSpeech`: короткий текст — один кусок; абзацы и предложения не рвутся без нужды; каждый кусок не длиннее лимита; склейка кусков сохраняет все непробельные символы; слово длиннее лимита режется.
  - `SpeechService.listen` на заглушках из `speech.service.spec.ts`: свежий синтез (N кусков по порядку, одно списание на всю длину, строка реестра); кэш-хит бесплатен; предпроверка баланса не зовёт провайдера; проигранная гонка списания удаляет строку и отдаёт 402; отказ провайдера ничего не списывает; потолок, пустой текст, лимит частоты; `assistant` из тела выбирает голос этого ассистента, без него — `preferred_agent`; в `speech_clips` ничего не пишется.
  - Контроллер: отображение ошибок на статусы.
  - Тесты `synthesize` остаются зелёными без правок.
- **Фронт (vitest, на ноде):**
  - `speechText.test.ts`: разметка, служебные теги, маркеры, эмодзи, таблицы, пустой результат.
  - Тест плеера на стенде `src/test/dom.tsx`: надписи по фазам; повторное нажатие останавливает; второй ответ глушит первый; 402 даёт тост и возвращает «Прослушать»; повтор не ходит на бэк.
  - Сторож связки в `ChatInterface`.
  - `check-locales`, `check-hardcoded`, `check-locale-format`.
- **Руками на test.linkeon.io после выката на test:**
  - русский ответ звучит выбранным в настройках голосом;
  - в «Истории» есть строка «Озвучка ответа»;
  - повтор бесплатен;
  - ответ длиннее 2000 знаков играет без пауз между кусками;
  - кнопка «Остановить» и переключение между ответами работают;
  - строка под ответом не ломается на ширине 375 px.

Flutter-приложение, TG-бот, автоозвучка новых ответов, скорость чтения, скачивание файла, выбор голоса прямо в чате, озвучка сообщений пользователя.

## Выкат

`deploy.sh` без флагов (test → smoke → prod → smoke) — только после явного «ок» владельца. Бэк катится раньше фронта в каждой фазе. Фронт без нового бэка получит 404 и покажет «не удалось озвучить». Старый фронт ручку не зовёт.
