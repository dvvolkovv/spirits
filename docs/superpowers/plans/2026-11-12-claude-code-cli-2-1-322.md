# Claude Code CLI 2.1.322 / Agent SDK 0.3.322 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Перевести все найденные активные runtime проекта на Claude Code CLI `2.1.322`, а backend Agent SDK — на `0.3.322`, не обрывая живые ходы и не оставляя скрытых старых путей запуска.

**Architecture:** Сначала выполняются read-only preflight и проверки кода в отдельном CI-клоне. Системные CLI обновляются native installer с атомарным переключением `/usr/bin/claude`; relay sandbox меняется под существующими lock и drain. Backend, relay-agent и product Dockerfile изменяются одним коммитом. Полный `deploy.sh` после доставки target SHA на product-хост выполняет `DRY_RUN → REHEARSE → боевой rollout`, поэтому клиентские контейнеры пересоздаются только из уже проверенного image ID.

**Tech Stack:** Claude Code native installer, Homebrew cask, Node.js 22, npm, NestJS/TypeScript, Jest, Node `node:test`, PM2, Docker, Bash, `scripts/deploy-relay.sh`, `scripts/deploy.sh`, `scripts/product-image-roll.sh`.

## Обязательные ограничения

- Не менять model ID, промпты или поведение трёх SDK call site.
- Не использовать `sudo npm install -g`, ручной `rsync`, ручной `scp` проектных файлов или правку живых чекаутов.
- Backend собирается только `npm`; frontend этим изменением не затрагивается.
- Сборки и тесты выполняются на `dv@85.192.61.231` в отдельном клоне под `~/ci/`, не на Mac и не в живых `~/spirits_back` / `~/spirits_front`.
- Не запускать `deploy-relay.sh` или `deploy.sh` без отдельного явного разрешения владельца непосредственно перед выкатом. Не использовать `PROD_ONLY`, `TEST_ONLY`, `FRONT_ONLY`, `BACK_ONLY`, `SKIP_SMOKE`, `SKIP_TEST_SMOKE`, `SKIP_PROD_SMOKE`, `FORCE_RESTART` или `SKIP_PRODUCTS_HOST`.
- `PRODUCT_IMAGE_REHEARSE=claude-21322` — не skip-флаг: он добавляет обязательные dry-run и репетицию перед боевым PHASE 4.
- Если PHASE 5 недоступна, остановиться за дополнительным решением владельца; не подставлять `SKIP_BOTS=1` самовольно.
- Любой красный health при закрытом relay admission оставляет drain включённым до восстановления и повторной проверки.
- На Linux/npm, relay runtime и Docker images старые бинарники и образы в рамках задачи не удалять: они нужны для отката. На Mac штатный brew upgrade удалил прежний cask 2.1.280; явный brew cleanup не запускался, но Homebrew дополнительно выполнил автоматическую периодическую очистку formula/dependency/cache. Локальной копии Mac CLI 2.1.280 не осталось.

## Уточнение спецификации, необходимое для правильного порядка

`product-image-roll.sh` отказывается собирать target SHA, пока содержимое `/opt/linkeon-host-agent` на product-хосте не совпадает с этим SHA. Эти исходники доставляет `ensure_host_agent` в PHASE 4 непосредственно перед `ensure_product_image`. Поэтому отдельная репетиция target SHA **до** `deploy.sh` технически невозможна без преждевременного обновления host agent.

В план добавлен небольшой hook `PRODUCT_IMAGE_REHEARSE` в `scripts/deploy.sh`. В боевой ветке `ensure_product_image`, уже после успешного `ensure_host_agent`, он последовательно запускает:

1. `DRY_RUN=1 SOURCE_SHA="$PH_PROD_SHA"`;
2. `REHEARSE=claude-21322 SOURCE_SHA="$PH_PROD_SHA"`;
3. обычный `SOURCE_SHA="$PH_PROD_SHA"` rollout без повторной сборки уже проверенного образа.

Это реализует одобренный порядок без гонки с работающим deployment-скриптом и без ручной раскладки исходников.

const fs = require('fs');
const path = require('path');

const deploy = fs.readFileSync(path.join(__dirname, '..', 'scripts', 'deploy.sh'), 'utf8');

function section(startMarker, endMarker, from = 0) {
  const start = deploy.indexOf(startMarker, from);
  const end = deploy.indexOf(endMarker, start);
  if (start < 0 || end < 0) throw new Error(`section not found: ${startMarker}`);
  return deploy.slice(start, end);
}

describe('PHASE 4: репетиция образа перед боевым rollout', () => {
  const image = section('ensure_product_image() {', '\n# Наблюдение за ЖИВЫМ агентом');
  const checkOnlyAt = image.indexOf('if [[ -n "${PH_CHECK_ONLY:-}" ]]');
  const writeAt = image.indexOf('\n  else', checkOnlyAt);
  const write = image.slice(writeAt);

  it('после доставки исходников делает dry-run, rehearsal и только затем боевой roll', () => {
    const dry = write.indexOf('\n      DRY_RUN=1 SOURCE_SHA="$PH_PROD_SHA" bash "$roll" "$PH_TARGET"');
    const rehearsal = write.indexOf('\n      REHEARSE="$PRODUCT_IMAGE_REHEARSE" SOURCE_SHA="$PH_PROD_SHA" bash "$roll" "$PH_TARGET" || {');
    const actual = write.indexOf('\n    SOURCE_SHA="$PH_PROD_SHA" bash "$roll" "$PH_TARGET" || rc=$?');

    expect(checkOnlyAt).toBeGreaterThan(-1);
    expect(writeAt).toBeGreaterThan(checkOnlyAt);
    expect(dry).toBeGreaterThan(-1);
    expect(rehearsal).toBeGreaterThan(dry);
    expect(actual).toBeGreaterThan(rehearsal);
  });

  it('красная репетиция прерывает машину до боевого roll', () => {
    const rehearsal = write.indexOf('\n      REHEARSE="$PRODUCT_IMAGE_REHEARSE" SOURCE_SHA="$PH_PROD_SHA" bash "$roll" "$PH_TARGET" || {');

    const onFailure = write.slice(rehearsal, close);

    expect(actual).toBeGreaterThan(close);

set -euo pipefail

BIN=/opt/linkeon-agent/bin
DRAIN_FILE=/tmp/linkeon-relay-drain

inflight_count() {

    let raw = "";
    process.stdin.on("data", (chunk) => { raw += chunk; });
    process.stdin.on("end", () => {
      const health = JSON.parse(raw);
      if (!Number.isInteger(health.inflight) || health.inflight < 0) process.exit(1);
      console.log(health.inflight);
    });

finish() {
  local status=$?
  trap - EXIT
  if [[ "$GATE_CREATED" -eq 0 ]]; then exit "$status"; fi

    rm -f -- "$DRAIN_FILE"
    GATE_CREATED=0

    sudo -n ln -s "claude-runtime-$PREVIOUS" "$BIN/.claude-runtime.rollback.$$"
    sudo -n mv -Tf "$BIN/.claude-runtime.rollback.$$" "$BIN/claude-runtime"

  if [[ "$("$BIN/claude-runtime" --version)" == "$PREVIOUS (Claude Code)" ]] \

    echo "Прежний runtime работает, drain снят" >&2

  fi

flock -n 9 || { echo "Другой rollout держит $LOCK_FILE" >&2; exit 1; }

[[ "$(/usr/bin/claude --version)" == "$VERSION (Claude Code)" ]]

INITIAL_INFLIGHT=$(inflight_count)

( umask 077; printf '%s\n' "$VERSION" > "$DRAIN_FILE.tmp.$$" && mv "$DRAIN_FILE.tmp.$$" "$DRAIN_FILE" )
GATE_CREATED=1

DRAIN_STARTED=$SECONDS
while true; do

fi

sudo -n mv -Tf "$BIN/.claude-runtime.next.$$" "$BIN/claude-runtime"
SWITCHED=1

for binary in /usr/bin/claude "$HOME/.local/bin/claude" "$BIN/claude-runtime" "$BIN/claude"; do
