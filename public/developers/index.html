Linkeon API: подключение к ассистентам

Внешний сервис входит в уже существующий аккаунт Linkeon, получает пару токенов и разговаривает с ассистентами этого аккаунта по HTTPS. Ответ приходит потоком строк JSON, работа ассистентов оплачивается токенами с баланса аккаунта.

Базовый адрес: https://my.linkeon.io · Обновлено 3 ноября 2026

Как это работает#

  1. ВходВойдите в существующий аккаунт по его телефону и коду из SMS.
  2. ТокеныВ ответ придут access-token и refresh-token.
  3. РазговорПередавайте access-token в заголовке и пишите ассистенту: ответ придёт потоком.
  4. ПродлениеРаз в два часа обменивайте refresh-token на новую пару.
  • Сервис действует от имени аккаунта. Разговоры, история и списания те же, что в кабинете my.linkeon.io.
  • Один аккаунт — один человек. Ассистенты запоминают собеседника и собирают его профиль из разговоров. Не ведите через один аккаунт разговоры разных людей: пусть каждый подключает свой.
  • Аккаунт заводят и пополняют в кабинете. Там принимают условия сервиса и оплачивают токены; оплаты через API нет.
  • Все пути начинаются с /webhook/. Это исторический префикс: запросы делает ваш сервис, обратных вызовов от нас нет. Тела запросов и ответов — JSON в UTF-8.

Быстрый старт#

Три запроса: код в SMS, токены по коду и вопрос ассистенту Роману (id 12). Вместо 7XXXXXXXXXX подставьте номер аккаунта.

# 1. Код придёт в SMS на номер аккаунта
curl "https://my.linkeon.io/webhook/898c938d-f094-455c-86af-969617e62f7a/sms/7XXXXXXXXXX"

# 2. Код из SMS → токены
curl -X POST "https://my.linkeon.io/webhook/a376a8ed-3bf7-4f23-aaa5-236eea72871b/check-code" \
  -H "Content-Type: application/json" \
  -d '{"phone":"7XXXXXXXXXX","code":"123456"}'

# 3. Вопрос ассистенту, ответ потоком
curl -N -X POST "https://my.linkeon.io/webhook/soulmate/chat" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"message":"Привет! Что ты умеешь?","assistantId":12}'

Вход в существующий аккаунт#

Сервис входит по телефону аккаунта и коду из SMS. Код вводит человек один раз, при подключении. Дальше сервис сам продлевает доступ refresh-токеном (см. Токены), и новые SMS не нужны.

Входите в кабинет по почте, через Google, Яндекс или Apple? Сначала привяжите к аккаунту телефон: Настройки → «Способы входа». Иначе вход по коду заведёт на этот номер новый, пустой аккаунт.

Номер передают только цифрами, с кодом страны и без «+»: для России это 11 цифр, начиная с 7. В примерах вместо номера стоит 7XXXXXXXXXX.

Шаг 1. Запросить код#

GET/webhook/898c938d-f094-455c-86af-969617e62f7a/sms/{phone}без токена

Отправляет на номер шестизначный код. Ответ 200 с текстом SMS sent одинаков для любого номера: по нему нельзя узнать, есть ли у номера аккаунт.

Код действует 5 минут и даёт 5 попыток. Пока он действует, повторный запрос тоже отвечает SMS sent, но новой SMS не шлёт — вводите код из первой. Новый код можно получить, когда прежний истёк, использован или погашен неверными попытками: не чаще раза в минуту, до 3 раз в час и 5 раз в сутки на номер.

Шаг 2. Обменять код на токены#

Токены#

ТокенСрокКуда передавать
access-token2 часав каждый запрос: Authorization: Bearer <access-token>
refresh-token30 днейтолько в запрос обновления пары
POST/webhook/auth/refreshrefresh-token

Передайте refresh-token в заголовке Authorization: Bearer <refresh-token>, тело не нужно. Ответ 200 — новая пара {"access-token": "…", "refresh-token": "…"}: сохраните оба токена. 401 {"error":"Invalid refresh token"} значит, что refresh-токен истёк или аккаунт удалён: войдите заново.

curl -X POST "https://my.linkeon.io/webhook/auth/refresh" \
  -H "Authorization: Bearer $REFRESH_TOKEN"
  • Обновляйте заранее — когда до конца срока access-токена остаётся минут 15. Срок записан в самом токене: это JWT, поле exp — время истечения в секундах Unix.
  • На 401 обновите пару один раз и повторите исходный запрос. Снова 401 — войдите заново.
  • Сервису, который обновляет пару хотя бы раз в 30 дней, входить заново не нужно.

Токен открывает весь аккаунт: разговоры, профиль и баланс. Сузить его права нельзя, отозвать выданный токен — тоже: сервис, который вовремя обновляет пару, сохраняет доступ, пока существует аккаунт. Подключайте только сервисы, которым доверяете. Храните токены на сервере, как пароль, и не отдавайте их в браузер или приложение посторонних людей.

Поток ответа#

Ответ 200 приходит потоком: Content-Type: text/plain; charset=utf-8, каждая строка — отдельный JSON-объект.

{"type":"begin"}
{"type":"item","content":"Здравствуйте! "}
{"type":"ping"}
{"type":"item","content":"Начнём с главного: кто сдаёт и на какой срок?"}
{"type":"end","content":"Здравствуйте! Начнём с главного: кто сдаёт и на какой срок?","usage":{"input":0,"output":1840,"total":1840}}
typeКогда приходитЧто делать
beginпервой строкойход начался
itemпо мере ответаcontent — очередной кусок текста. Кусков бывает один или много: показывайте их по мере прихода
pingне реже раза в 30 секунд, пока ассистент работает молчапропустить: соединение живо
endпоследней строкойcontent — итоговый текст ответа, usage.total — сколько токенов ушло на ход. "reason": "no_tokens" — кончился баланс

Итог — всегда end.content: из него убраны служебные пометки, которые могли проскочить в кусках item. По end замените показанные куски на этот текст, а если нужен только итог — просто ждите end. Незнакомые типы событий пропускайте. Поле ui в запрос не добавляйте: оно включает события для интерфейса кабинета.

Ответ написан в Markdown. В нём бывают кнопки и ссылки кабинета: {{button: Текст | action: …}} и {{link: Текст | url: /путь}}. Покажите из них текст или вырежьте; путь в link ведёт в кабинет, к нему добавьте https://my.linkeon.io. Файлы, которые подготовил ассистент, приходят ссылками вида [Скачать отчёт.pdf](адрес). Такие ссылки открываются без входа — не показывайте их посторонним.

Правила хода#

  • Ход может идти долго. Обычный ответ занимает секунды, большая работа — документы, поиск, файлы — до 20–30 минут. Общий таймаут на ответ не ставьте, а ожидание очередной строки ограничьте 2 минутами: ping приходит не реже раза в 30 секунд.
  • Одно сообщение за раз. Не отправляйте тому же ассистенту новое сообщение, пока не пришёл end: оно может прервать текущий ход. Идёт ли ход сейчас, покажет GET /webhook/chat/active-turn?assistantId=10 с токеном: {"active": true, "startedMsAgo": 42000}.
  • Обрыв связи ход не останавливает. Ассистент доведёт ответ, и он появится в истории — читайте её, а не отправляйте сообщение заново. Повтор того же текста вскоре после хода у большинства ассистентов вернёт служебную реплику с usage.total = 0, у остальных станет новым ходом с новым списанием.
  • Сбой посреди хода приходит не HTTP-ошибкой, а текстом в том же потоке: end с сообщением о сбое. То, что ассистент успел ответить, сохранится в истории.
  • Без действующего токена чат отвечает 200 с пустым телом, а не 401. Если в потоке не пришло ни одной строки, обновите пару токенов и повторите запрос.

Файлы#

POST/webhook/agent/upload-and-chatнужен токен

Сообщение с файлами, multipart/form-data. Поля: assistantId, message — что сделать с файлами, и до 10 файлов в полях files, всего до 100 МБ за запрос. Ответ — тот же поток событий. Передавайте assistantId всегда: без него файлы уйдут Роману в отдельный разговор.

curl -N -X POST "https://my.linkeon.io/webhook/agent/upload-and-chat" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -F assistantId=9 \
  -F "message=Проверь акт сверки" \
  -F files=@act.pdf

Больше 100 МБ — 413 с {"error":"file_too_large"} или {"error":"batch_too_large"}; запрос без файла — 400 {"error":"No file uploaded"}. Больше 10 файлов ассистент не примет: в потоке придёт сообщение об ошибке.

DELETE/webhook/chat/history?assistantId=10нужен токен

Стирает историю разговора с ассистентом, и в кабинете тоже. Ответ {"success": true}. Ассистент при этом может помнить стёртый разговор: его рабочая память не сбрасывается. Профиль, который ассистенты собрали о человеке, тоже остаётся.

Баланс#

GET/webhook/user/tokensнужен токен
Ответ 200
{ "success": true, "tokens": 48750 }
  • usage.total в end — стоимость хода по расчёту в момент ответа, вместе с картинками, видео и озвучкой. Возврат за сорвавшийся ход в нём не виден. tokensUsed в истории — стоимость только текста. Точный остаток — в /webhook/user/tokens.
  • Цена зависит от работы: короткий ответ дешевле поиска в интернете или подготовки документа.
  • Когда токены кончаются, ассистент не отвечает: в потоке приходит текст о пополнении, а в end — "reason": "no_tokens".
  • Пополнить баланс можно в кабинете: my.linkeon.io/tokens.

  • Ход: один на ассистента одновременно; большая работа — до 20–30 минут; ping — не реже раза в 30 секунд.

  • Браузер: CORS открыт для любого источника, но токены — секрет аккаунта. Ходите в API с вашего сервера.

Пример целиком#

Скрипт входит по SMS, находит Романа и задаёт ему вопрос, печатая ответ по мере прихода. Нужны Python 3.9+ и библиотека requests.

ask.py
"""Linkeon API: вход по SMS и вопрос ассистенту.

Нужны Python 3.9+ и requests: pip install requests
"""
import json

import requests

BASE = "https://my.linkeon.io/webhook"
PHONE = "7XXXXXXXXXX"  # номер аккаунта: 11 цифр, без «+»
SMS = "898c938d-f094-455c-86af-969617e62f7a/sms"
CHECK = "a376a8ed-3bf7-4f23-aaa5-236eea72871b/check-code"


class TokenExpired(Exception):
    """Поток пришёл пустым: access-токен истёк или не передан."""


def login(phone):
    requests.get(f"{BASE}/{SMS}/{phone}", timeout=30).raise_for_status()
    code = input("Код из SMS: ").strip()
    r = requests.post(f"{BASE}/{CHECK}", json={"phone": phone, "code": code}, timeout=30)
    r.raise_for_status()
    tokens = r.json()
    if tokens.get("is-new-user"):
        raise SystemExit("Номер не был привязан к аккаунту: сервер завёл новый, пустой")
    return tokens


def refresh(tokens):
    r = requests.post(
        f"{BASE}/auth/refresh",
        headers={"Authorization": f"Bearer {tokens['refresh-token']}"},
        timeout=30,
    )
    r.raise_for_status()
    return r.json()


def ask(tokens, assistant_id, message):
    """Печатает ответ по мере прихода и возвращает событие end."""
    r = requests.post(
        f"{BASE}/soulmate/chat",
        headers={"Authorization": f"Bearer {tokens['access-token']}"},
        json={"message": message, "assistantId": assistant_id, "tz": "Europe/Moscow"},
        stream=True,
        timeout=(10, 120),  # ждать строку до 2 минут: ping приходит не реже раза в 30 с
    )
    r.raise_for_status()
    r.encoding = "utf-8"
    events, final, buffer = 0, None, ""

    def handle(line):
        nonlocal events, final
        if not line.strip():
            return
        events += 1
        event = json.loads(line)
        if event["type"] == "item":
            print(event["content"], end="", flush=True)
        elif event["type"] == "end":
            final = event

    for chunk in r.iter_content(chunk_size=None, decode_unicode=True):
        buffer += chunk
        *lines, buffer = buffer.split("\n")
        for line in lines:
            handle(line)
    handle(buffer)
    print()
    if events == 0:
        raise TokenExpired()
    return final  # None — поток закончился без end: ответ ищите в истории


if __name__ == "__main__":
    tokens = login(PHONE)
    agents = requests.get(f"{BASE}/agents", params={"lang": "ru"}, timeout=30).json()
    roman = next(a for a in agents if a["name"] == "Роман")
    question = "Привет! Что ты умеешь?"
    try:
        end = ask(tokens, roman["id"], question)
    except TokenExpired:
        tokens = refresh(tokens)
        end = ask(tokens, roman["id"], question)
    if end:
        print("Списано токенов:", end["usage"]["total"])

То же на Node.js 18+, без зависимостей. Токены скрипт берёт из переменных окружения: ACCESS_TOKEN=… REFRESH_TOKEN=… node ask.mjs.

ask.mjs
const BASE = "https://my.linkeon.io/webhook";

async function refresh(tokens) {
  const res = await fetch(`${BASE}/auth/refresh`, {
    method: "POST",
    headers: { Authorization: `Bearer ${tokens["refresh-token"]}` },
  });
  if (!res.ok) throw new Error(`refresh: HTTP ${res.status}`);
  return res.json();
}

async function ask(tokens, assistantId, message, onText) {
  const res = await fetch(`${BASE}/soulmate/chat`, {
    method: "POST",
    headers: {
      Authorization: `Bearer ${tokens["access-token"]}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({ message, assistantId, tz: "Europe/Moscow" }),
  });
  if (!res.ok) throw new Error(`chat: HTTP ${res.status}`);

  const decoder = new TextDecoder(); // один на весь поток, иначе кириллица рвётся
  let buffer = "";
  let events = 0;
  let end = null;
  const handle = (line) => {
    if (!line.trim()) return;
    events += 1;
    const event = JSON.parse(line);
    if (event.type === "item") onText(event.content);
    if (event.type === "end") end = event;
  };
  for await (const chunk of res.body) {
    buffer += decoder.decode(chunk, { stream: true });
    const lines = buffer.split("\n");
    buffer = lines.pop();
    lines.forEach(handle);
  }
  handle(buffer + decoder.decode());
  if (events === 0) throw new Error("token_expired");
  return end; // null — поток закончился без end: ответ ищите в истории
}

let tokens = {
  "access-token": process.env.ACCESS_TOKEN,
  "refresh-token": process.env.REFRESH_TOKEN,
};
const question = "Привет! Что ты умеешь?";
const print = (text) => process.stdout.write(text);
let end;
try {
  end = await ask(tokens, 12, question, print);
} catch (e) {
  if (e.message !== "token_expired") throw e;
  tokens = await refresh(tokens); // сохраните новую пару
  end = await ask(tokens, 12, question, print);
}
console.log(`\nСписано токенов: ${end?.usage.total ?? "неизвестно"}`);
